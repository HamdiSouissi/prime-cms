# Internationalisation (i18n)

Prime CMS est entièrement traduisible : administration, installeur, pages d'erreur, e-mails,
thème Aurora et plugin de référence. Le français est la langue de référence, l'anglais est livré.

## 1. Catalogues

```
resources/lang/{fr,en}/core.php      # noyau, rôles, capacités, types de contenus, réglages
resources/lang/{fr,en}/admin.php     # interface d'administration (+ admin.js.* pour le JS)
resources/lang/{fr,en}/site.php      # site public et thème Aurora
content/plugins/<slug>/lang/{fr,en}/messages.php   # clés « plugin::<slug>.x.y »
content/themes/<slug>/lang/{fr,en}/messages.php    # clés « theme::<slug>.x.y »
```

- Paramètres : `:name` (`t('admin.mail.resent', ['to' => $email])`).
- Pluriels : `un|plusieurs`, ou formes explicites `{0}Aucun|{1}Un|[2,*]:count` — comprises à
  l'identique par `Translator::choice()` (PHP) et `trChoice()` (JS).

## 2. API

| Contexte | Appel |
|----------|-------|
| PHP | `t('core.x')`, `tc('core.x', $n)`, `format_date()`, `format_datetime()`, `locale_formatter()` |
| Vues | `$this->t('admin.x')`, `$this->choice('admin.x', $n)` |
| Contrôleurs admin | trait `TranslatesAdminCopy` → `$this->t()` |
| JavaScript | `import { tr, trChoice } from './i18n.js'` — `tr(key, fallback, params)` |

Le catalogue JS (`core.*` et `admin.*`) est injecté dans le layout admin sous forme de
`<script type="application/json" data-prime-translations>` ; `i18n.js` s'initialise seul à
l'import, ce qui permet aux modules de traduire dès leur chargement.

### Libellés stockés comme données

Menus, types de contenus, taxonomies, capacités, blocs, manifestes `theme.json`/`plugin.json`,
champs de réglages : ces libellés sont des **données**. Ils peuvent contenir une clé
(`core.content_types.post.plural`, `plugin::hello-prime.fields.rating`) ou un littéral ;
`Prime\Content\LabelTranslator::resolve()` traduit les clés et laisse passer le reste.

## 3. Choix de la langue

- `language.site` : langue du site public ; `language.admin` : langue imposée à l'admin (vide = langue du profil).
- `language.per_user` : chaque utilisateur choisit sa langue dans son profil.
- `language.detect_browser` : suit `Accept-Language` sur le site public.
- `language.fallback` : langue de secours pour les clés manquantes.

## 4. Contrôle qualité

```bash
php bin/prime lang:check            # erreurs : clé manquante, clé inconnue, texte en dur
php bin/prime lang:check --strict   # échoue aussi sur les avertissements (clés inutilisées…)
```

Une clé est « utilisée » si elle apparaît dans un appel de traduction, comme littéral exact
(libellé stocké en donnée), ou sous un préfixe dynamique (`t('core.media.kinds.' . $kind)`).
Les clés volontairement sans appel direct vont dans `resources/lang/unused-baseline.php`.
La CI exécute `lang:check --strict`.

## 5. Hooks

`translations.register` (filtre : reçoit le `Translator`, `register($locale, $messages)`),
`translations.missing`, `locale.resolved`, `locale.changed` (événements).
