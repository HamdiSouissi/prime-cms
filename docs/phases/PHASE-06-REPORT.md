## 2. Sécurité, architecture et qualité vérifiées

- **Zéro dépendance au runtime** : PHP 8.2+ natif (`DOMDocument`, PDO, JSON), ES2022 natif sans bundler ni dépendance npm, fonctionnement vérifié sans `vendor/` (`php bin/prime content:types`).
- **Sécurité par défaut** :
  - Assainissement HTML basé exclusivement sur liste blanche (`HtmlSanitizer`), bloquant XSS, `javascript:`, attributs `on*` et balises actives.
  - Bloc `html` brut restreint à `content.unfiltered_html` ; préservation non destructive lors des éditions par un rôle éditeur/auteur.
  - CSP globale stricte préservée sur 100 % des routes admin ; `frame-src` limité à `youtube-nocookie.com` et `player.vimeo.com` uniquement sur la vue d'aperçu.
  - CSRF systématique sur toutes les mutations (formulaires, actions en lot, autosave JSON, heartbeat/reprise de verrou, création rapide de termes).
- **Extensibilité prouvée** : `hello-prime` (`v1.1.0`) ajoute un CPT, une taxonomie, un groupe de champs personnalisés et un bloc Prime Editor complet (serveur + client JS) uniquement via `PluginContext`, sans aucune modification du noyau, et se désinstalle proprement sans laisser aucune ligne orpheline.
- **Vérification qualité locale** :
  - **PHPStan niveau 8** (`src/` + `content/plugins/hello-prime/src/`) : `[OK] No errors`.
  - **Tests PHP (PHP 8.2 & 8.3)** : **403 passés, 0 échec** (4 830 assertions), plus tests MySQL 8.0 / MariaDB 10.6 (`#[Group('database')]`).
  - **Tests JS (Node 22)** : **13 passés, 0 échec** + `node --check` sur l'ensemble des modules ES.

### Détail de la vérification interactive (C8)

L'environnement sandbox ne disposant d'aucun binaire navigateur graphique/headless (Chromium, Firefox ou Playwright non installés), aucune capture PNG n'a été générée dans `docs/phases/screens/phase-06/`. À la place, une vérification automatisée reproductible a été exécutée sur les **vrais documents HTML rendus par `Prime\Http\Kernel`**, associés au fichier compilé `public/assets/admin/css/admin.css` et aux modules ES2022 natifs sous JSDOM (Node 22) :

1. **Audit `[hidden]` (C1)** : **107 éléments** porteurs de l'attribut `hidden` à travers 12 écrans réels ont tous retourné `getComputedStyle(el).display === 'none'` — en particulier `[data-prime-lock-lost-banner]` (caché pour le titulaire du verrou avant et après édition), `[data-prime-table-bulk-bar]`, `.pc-ed-slash-menu`, `.pc-ed-block-popover` et `.pc-ed-toolbar`.
2. **Parcours clavier complet (C3)** : exécuté de bout en bout sur le vrai HTML de `/admin/content/post/{id}/edit` :
   `titre → Entrée (focus bloc 0) → Flèche haut (retour titre) → Flèche bas (bloc 0) → paragraphe → Entrée → / (palette globale reste fermée) → /titre → Entrée (menu fermé, focus .pc-ed-h-input) → texte du titre → Entrée → /liste → Entrée (focus 1er élément) → 2 éléments via Entrée → Ctrl+Z (annulation, focus conservé dans l'éditeur) → Ctrl+Shift+Z (rétablissement, focus conservé) → Ctrl+S (soumission du formulaire avec JSON sérialisé complet)`.
3. **Onglets de la liste (C2)** : sur les 7 écrans (`all`, `published`, `draft`, `pending`, `scheduled`, `private`, `trash`), le nombre exact de lignes `<tbody> tr` correspond 1:1 au compteur de chaque onglet.
4. **Contributeur (C6) & CTA discret (C7)** : vérifiés sur le HTML réel de `/admin/content/post/create` (bouton principal « Soumettre pour relecture » `data-prime-submit-status="pending"`, secondaire « Enregistrer le brouillon » `draft`), `/admin/content/post/{pendingId}/edit` (bandeau lecture seule, aucun bouton de sauvegarde) et `/admin/content/post/{id}/edit` (`.pc-btn--danger-outline` en barre latérale, aucun `.pc-btn--danger` plein).
5. **Viewport mobile 375 px** : règles `@media (max-width: 640px)` vérifiées dans le CSS compilé sur `.pc-editor-topbar`, `.pc-editor-sheet`, `.pc-ed-block`, `.pc-content-tabs`, `.pc-content-filters` et `.pc-table`.
